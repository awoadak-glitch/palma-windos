# فحص تحديثات PALMA VISION 2.4.0

نجحت 48 تجربة Node.js: 25 فحصًا لاستمرار إدارة الجلسات والبروتوكول ومسار
الأنمي، و23 فحصًا للتحديث. تشمل التحقق من المصدر والإصدار والحجم والبصمات،
الحزم التالفة، إلغاء التنزيل، منع تفعيل تنزيل ناقص، اعتماد إصدار جديد،
الرجوع بعد فشل البدء، عزل الطلبات، ومنع إعادة التشغيل أثناء تنزيل فيديو.

فُحصت صياغة JavaScript وسلامة كل ملف داخل ASAR وZIP أثناء البناء.
لم ينجح تشغيل Electron أو Chromium في بيئة الفحص المحلية؛ منع النظام
إنشاء المقبس المحلي اللازم لبدء المتصفح قبل وصوله إلى كود التطبيق.
لذلك لم يُختبر ملف BAT ولا تشغيل الواجهة أو دورة التحديث كاملة على Windows هنا.

يتضمن GitHub workflow فحصًا مطلوبًا على Windows باستخدام Electron 44.7.2:
بدء النسخة المرفقة، استيراد تحديث ASAR، طلب التحقق من الجاهزية من واجهة
معزولة عبر البروتوكول الحقيقي، ثم الرجوع بعد تحديث تجريبي معطوب.
لا تُنشر Release إذا فشل الفحص. تظهر نتيجة فحص كل إصدار وسجلاته في صفحة
Actions لمستودع awoadak-glitch/palma-windos.

الحزمة الأولية 2.4.0 التي سُلّمت قبل إنشاء المستودع تحتاج إدخال رابط المستودع
في الواجهة مرة واحدة. تضمّنه حزم GitHub التالية أثناء البناء. لا يوجد GitHub Token داخل العميل.
بصمات SHA-256 تتحقق من سلامة الحزمة؛ مصدر الثقة هو HTTPS والمستودع المحدد.

لم تُجرَ اختبارات مشاهدة فيديو أو إصلاحات جديدة للقنوات في هذه المهمة.
